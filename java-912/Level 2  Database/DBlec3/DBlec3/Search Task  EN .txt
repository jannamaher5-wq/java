1. String Comparison in SQL
When you write a query like this:

SQL
SELECT *
FROM employees
WHERE first_name > 'ahmed'
  AND first_name < 'ali';
How does the database evaluate and execute this?
Lexicographical Order: The database does not evaluate words by meaning; it compares text character by character based on standard alphabetical order (specifically, the ASCII/Unicode values of the characters).

Character-by-Character Comparison:

It begins by comparing the first character of the first_name with the first character of 'ahmed'.

If the first characters match, it moves to the second character, and so on.

Expected Result Set:

Any name that alphabetically comes after 'ahmed' AND before 'ali'.

Matching Examples: akram (since ak comes after ah), alaa (since ala comes after ahm and before ali), and amr (since am comes before al).

Non-Matching Examples: 'ahmed' itself and 'ali' are excluded (because strictly greater > and strictly less < operators do not include equality =), as well as names like baher or zaki because they come after ali.

Important Note: String comparison is case-sensitive depending on your database engine and collation settings (for example, in Oracle or MySQL if case sensitivity is enabled).

2. The ROWNUM Mechanism in Oracle
First, it is important to understand that ROWNUM is a pseudo-column in Oracle. It is assigned dynamically to rows in memory as they are retrieved.

SQL
-- Query 1 (Executes and returns a result)
SELECT * FROM employees WHERE ROWNUM = 1;

-- Query 2 (Returns no data!)
SELECT * FROM employees WHERE ROWNUM = 2;

-- Query 3 (Returns no data!)
SELECT * FROM employees WHERE ROWNUM = 3;
Why does Query 1 work while Queries 2 & 3 return no rows?
To understand this, look at the order of execution inside Oracle:

Oracle fetches the candidate row from the table.

It assigns a temporary evaluation number: ROWNUM = 1.

It checks the WHERE clause condition to decide whether to accept or discard the row.

What happens in Query 1 (WHERE ROWNUM = 1):
Oracle fetches the first candidate row and assigns ROWNUM = 1.

It evaluates the condition: Does ROWNUM equal 1? Yes (1 = 1).

The condition passes, so Oracle includes this row in the result set.

What happens in Query 2 (WHERE ROWNUM = 2):
Oracle fetches the first row from the table and assigns it ROWNUM = 1.

It evaluates the condition: Does ROWNUM (which is currently 1) equal 2? No (1 = 2 is False).

Result: The first row is discarded.

Oracle moves to the second row in the table. However, since the previous row was discarded, this new row is now the first valid candidate, so Oracle assigns it ROWNUM = 1 again!

It evaluates the condition again: Does 1 equal 2? False again, so this row is also discarded.

Oracle continues this process through the entire table: every row fetched gets assigned ROWNUM = 1, fails the check (1 = 2), and gets discarded. Because no row ever successfully passes the filter, ROWNUM never increments to 2.
